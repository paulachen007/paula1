## 装到 iPhone 主屏幕，就是一个 App

这是 PWA，**不用上架 App Store、不用装任何东西**：

1. 用 **Safari** 打开 https://paulachen007.github.io/paula1/
2. 点底部中间的 **分享** 按钮
3. 选 **「添加到主屏幕」** → 命名 → 添加
4. 回到桌面，点新出现的图标即可

装好之后：

| 特性 | 说明 |
|:--|:--|
| 独立图标 | 桌面图标，不是 Safari 书签 |
| 全屏运行 | 没有地址栏和浏览器工具栏 |
| **启动画面** | 打开时显示金色星标启动图（9 种 iPhone 尺寸精确适配），不再闪白屏 |
| **断网可用** | Service Worker 缓存全部资源，飞行模式也能打开 |
| 无回弹 / 无缩放 | 关掉了 iOS 的下拉橡皮筋和双击缩放，手感接近原生 |
| 适配刘海 | 使用 `safe-area-inset`，内容不会被灵动岛或 Home 指示条遮住 |

> 说明：设计稿里的状态栏（9:41 / 信号 / 电池）和底部 Home 指示条**没有画进页面** —— 那是 iOS 系统界面，全屏运行时系统会自己绘制，再画一遍会重影。

## 设计还原来源

Figma 文件 `test-问答`（3 个 428×926 画板，实际为 2 个页面）。

设计规范是从 Figma API 直接读取的，不是靠肉眼估：

| 项 | 值（来自设计稿） |
|:--|:--|
| 字体 | **Almendra**（400 / 700 / 400 italic，已自托管） |
| 主文字 | `#E3E1DB` |
| 次级文字 / 卡片文字 | `#D0C7B8` |
| 金色小字与高亮 | `#AC8D56` |
| 主标题 | Almendra 36px w700 / 行高 46.656 |
| 卡片文字 | Almendra 24px w400 / 行高 31.104 |
| 答案卡片 | 224×383，圆角 15，描边 `#E3E1DB` 3px，竖向渐变 `#221E1E → #7E6D6D` |
| 输入条 | 353×46，圆角 23，填充 `#D0CCC9` @67%，描边 `#D0C7B8` 1px |
| 顶部圆按钮 | 44×44，奶油底 `#D0C7B8` + 深色图标 |
| 画板 | 428×926（等比缩放到各种机型） |

**实现方式**：页面按设计稿 428×926 的坐标绝对定位，再用 `transform: scale()` 等比缩放到当前机型（`scale = min(视口宽/428, 可用高/926)`），并扣除 `safe-area-inset`。所以任何屏幕比例下，版面都和设计稿完全一致。

## 两个页面

| 页面 | 内容 |
|:--|:--|
| **输入页** | 问候语、副标题、底部输入条（麦克风 + 键盘图标） |
| **解答页** | 问题、答案卡片、`View similar case` 按钮、底部输入条 |

交互映射：

底部输入条是主要入口，做了三种输入方式：

| 操作 | 行为 |
|:--|:--|
| **点胶囊任意位置** | 叫出系统键盘 —— 拼音、手写、英文都可以 |
| **点麦克风** | 语音输入（浏览器支持时）；不支持会明确提示并切到键盘 |
| **右侧按钮** | 空的时候是键盘图标（点它也叫键盘）；**输入文字后变成发送箭头**，点一下直接出答案 |
| **回车** | 直接提交 |

其他交互：

- **`View similar case`** → 同一问题再抽一条答案
- **主页按钮** → 回到输入页
- **分享按钮** → 系统分享面板，不支持时复制链接

### 输入条可见性（踩过的坑）

底部输入条一开始在部分机型上会被裁掉，原因是 `transform: scale()` **不改变布局尺寸** —— 舞台虽然视觉上缩小了，但仍按 428×926 参与居中，缩放后位置就跑偏了。

修法是外面套一层 `.frame`，它的尺寸是 `calc(428px * var(--s))`，**按缩放后的真实尺寸参与布局**，舞台用 `transform-origin: top left` 在里面缩放。另外视口高度取 `innerHeight` / `clientHeight` / `visualViewport.height` 的**最小值**再留 2% 余量，保证在任何解释下都完整可见。

实测 492×700 / 492×900 / 492×1100 三种窗口下输入条全部可见。

## 抽答案动效

点抽牌 / `View similar case` 时：

```
卡片绕竖轴转 3 整圈（1080°）  →  停 0.14s  →  答案文字淡入
      1.5s（每圈 0.5s）            --pause       0.45s
```

- 用 `rotateY(1080deg)` 配合 `perspective(1200px)`，是**绕竖轴的翻转**而不是平面旋转
- **转的过程中答案是隐藏的**（`animation-fill-mode: both` 让文字停在 `opacity:0`），所以不会看到字跟着转
- 转到一半时给卡片加一层淡金色外发光（`box-shadow` 在 55% 处最亮），收尾时收回
- 时长用 CSS 变量控制，改 `--spin` / `--pause` / `--fade` 即可
- 系统开启「减少动态效果」时自动跳过，直接显示答案

## 中英双语

**问题用什么语言问，就用什么语言回答。**

| 你问 | 得到的答案 |
|:--|:--|
| `我这次考试能过吗？` | 别指望运气，这门课需要实打实的时间投入。 |
| `他到底喜不喜欢我` | 你在回避一个已经很明显的事实。 |
| `Should I quit my job?` | Negotiate once more. There is **room** and they are waiting to see if you will ask. |

- **关键词库中英合并**（388 个），中文按子串匹配、英文按整词匹配（含简单复数）
- 实测：中文问题 **15/15** 正确，英文问题 **7/7** 正确
- **中文字体用宋体** —— 字体栈是 `'Almendra', "Songti SC", "STSong", "Noto Serif SC", …`，Almendra 没有中文字形，所以拉丁字母走 Almendra、汉字自动落到宋体
- 中文方块字在同样字号下视觉大得多，所以中文单独调小了字号与行距（`18.5px / 1.82`）
- 中文答案**自动高亮开头那句短判断**（对应设计稿里英文的金色强调）

## 技术说明

- **单页应用**：`index.html` + `answers.js`，无框架、无构建步骤
- **零 CDN**：字体、图片全部自托管，**断网可用**
- **PWA**：`manifest.json` + `sw.js` 离线缓存，可「添加到主屏幕」全屏运行
- **无追踪**：没有统计、广告或第三方脚本

## 文件结构

```
index.html      # 两个页面 + 全部样式与逻辑
answers.js      # 话题关键词 + 140 条英文答案库 + 识别函数
manifest.json   # PWA 清单
sw.js           # Service Worker 离线缓存
assets/         # 背景、人像、图标、玻璃按钮素材（WebP/SVG）
fonts/          # Almendra 字体（woff2，自托管）
icons/          # 应用图标（192/512/maskable/apple-touch/favicon）
preview.png     # 界面预览
qr.png          # 在线地址二维码
classic.html    # 上一版（中文塔罗）留档
```

## 本地运行

```bash
git clone https://github.com/paulachen007/paula1.git
cd paula1
python3 -m http.server 8000
# 打开 http://localhost:8000
```

> Service Worker 需要 HTTPS 或 localhost 才生效；直接双击 `index.html` 时页面正常但离线缓存不可用。
